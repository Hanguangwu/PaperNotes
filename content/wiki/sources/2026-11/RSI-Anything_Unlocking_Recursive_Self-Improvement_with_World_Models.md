> [!abstract]+ 一句话总结
>
> RSI-Anything 在 JEPA-Anything 的跨域预测基础上，用世界模型引导动作与反馈选择，并通过组件与兼容性检查保留更新后的策略–模型对，从而在有限外部反馈下实现可跨域复用的递归自我改进（代码修复成功率 26.3% → 31.2%；实验室规划五个保留版本得分 21.80% → 46.01%）。

## 原文摘要（译）

递归自我改进（RSI）旨在将交互经验转化为持久的能力提升，但外部反馈成本高昂，且随着策略演化，世界模型预测可能变得不可靠。本文提出 RSI-Anything，一个基于 JEPA-Anything 的领域通用框架，利用预测世界模型引导动作选择与学习数据筛选。观测到的反馈驱动策略或工作流改进，以及条件性世界模型适应；组件检查与兼容性检查共同决定更新后的策略–模型对是否被保留。在多种计算与科学领域中，RSI-Anything 均展现出显著收益：在代码修复中，固定编码器时，成功率从静态验证器的 26.3% 提升至预测选择的 29.2%，世界模型适应后进一步达到 31.2%，在线测试调用次数相当；图形用户界面评估显示任务完成率提高，平均动作数减少 39.4%；在五个连续策略版本中，实验室规划得分从 21.80% 提升至 46.01%，超过翻倍；在反应优化中，相同 40 次实验预算下，平均最优观测产率达到 96.15%，对比贝叶斯优化的 82.16%；端到端免疫科学应用进一步将工作流演化与预测建模连接到治疗假设生成。这些结果证明，预测世界模型与可保留的系统更新能够在多样环境中实现递归改进。

## 研究问题

在外部反馈昂贵、世界模型可能因策略漂移而失效的前提下，如何把单轮交互经验转化为可保留、能持续提升后续行动与学习能力的系统级改进？具体拆解为：

1. 引入世界模型预测后，候选选择是否优于静态验证器或随机选择？
2. 保留策略或模型更新后，是否能带来进一步增益？
3. 这些增益能否在有限外部反馈预算下实现，并迁移到计算任务与科学实验域？

## 核心贡献

1. **世界模型服务递归自我改进**：将预测世界模型系统性地嵌入 RSI 循环——用预测预判动作后果、优先收集反馈、引导学习数据构造；把「可持久改进」定义在策略–世界模型系统层面，并把策略演化下的预测可靠性作为核心设计约束。
2. **递归更新与保留机制**：连接预测引导的动作/数据选择与反馈驱动的策略学习或工作流修订，以及条件性世界模型适应；组件级检查评估单个更新，兼容性检查决定最终保留的策略–模型对，允许异步更新；保留对决定下一轮候选与学习经验，从而闭合递归环。
3. **跨域实证**：在代码修复、GUI 交互、物理域实验室规划、化学反应优化以及免疫科学端到端工作流中，均观察到可量化增益，且多数实验在严格对齐的在线反馈预算下完成。

## 数据与任务定义

论文在四个主要任务域与一个端到端科学应用中验证框架。

**代码修复**：固定编码器，每轮四个候选补丁，最多三轮反馈。评测集包括 `CodeContests`（200 题）、`APPS Introductory` 与 `LiveCodeBench v6`；主指标为隐藏测试全通过率与在线测试套件调用次数。

**图形界面（GUI）**：在 `MiniWoB++` 的 click-checkboxes（含动作级诊断）与 `OSWorld` 上评估任务完成率与平均动作数。

**实验室规划**：`LabHorizon F200` Level-2（200 任务），跟踪同一 `4B` 策略连续五个保留版本；指标为 `L1` 准确率与 `L2 Final Score`（动作序列相似度 + 参数精度）。

**反应优化**：两个 Suzuki–Miyaura 筛选（GC 分析的 Pd–NHC–DMS 与 flow LC–MS 的 Pd(OAc)₂）；在相同实验次数下与贝叶斯优化比较平均/最优观测产率。

**免疫科学端到端**：Agent Genesis 搜索科学 agent 工作流并构建动作条件免疫世界模型；分析 agent 结合模型预测与实验证据进行自校正与治疗假设生成。

任务形式化为：对每个域 $d$，

$$
\mathcal{T}_d = (X_d, S_d, A_d, W_d, V_d, M_d, C_d, B_d)
$$

分别表示观测/上下文、任务状态、动作空间、世界模型适配器、验证器、指标、约束与预算。

## 方法主线

### 总体架构

RSI-Anything 建立在 `JEPA-Anything` 的跨域预测基础之上。JEPA-Anything 采用联合嵌入预测架构与正交预测分解（OPF），将潜在目标分解为互补因子并分别学习预测器，再重组为完整潜在状态。RSI-Anything 在此之上闭合递归环：世界模型预测引导候选选择；外部反馈驱动策略或工作流更新，并在可靠性检查通过时触发世界模型适应；组件检查与兼容性检查决定是否保留新的策略–模型对。

### 机制流程

1. **输入与预测选择**：输入当前保留的策略参数与世界模型，结合任务上下文；世界模型对候选动作进行前瞻评估，按预期效用或信息增益排序并选择执行对象。
2. **执行与反馈**：仅对被选候选执行真实交互，获得预测–观测配对（测试结果、界面观测、实验产率等），更新反馈历史。
3. **条件更新**：根据反馈构造示范、偏好或工作流评分信号以更新策略；同时对当前模型版本做版本感知的可靠性评估，仅在判定为不可靠、数据充分且预算允许时触发世界模型适应。
4. **检查与保留**：组件检查评估策略任务效用或预测器质量；兼容性检查评估组装后的决策行为。通过检查的策略–模型对被保留，并决定下一轮候选分布与学习经验，从而闭合递归环。

### 关键设计细节

- **可靠性协议**：只使用当前模型版本生成的（或可重算的）预测；历史版本预测不直接混入当前误差估计；覆盖不足时返回「insufficient」而非「reliable」，且不触发适应。
- **异步更新**：策略与世界模型可独立更新；只有通过兼容性检查的组合才会被保留。
- **域适配**：各应用指定动作编码、结果读出（标量产率 / 潜在状态 / 测试通过）与启用路径（不确定性选择、多步规划、想象轨迹学习等）。

## 关键结果

### 代码修复

在 `CodeContests` 上（固定编码器，三轮，三随机种子）：

| 选择方法 | 隐藏测试全通过率 | 在线调用/任务 |
|----------|------------------|---------------|
| Random-K | 26.0% | 3.72 |
| 容量匹配静态验证器 | 26.3% | 3.72 |
| RSI-Anything + 固定世界模型 | **29.2%** | 3.71 |
| RSI-Anything + 世界模型适应 | **31.2%** | 3.72 |

在 `APPS Introductory` 与 `LiveCodeBench v6` 上，固定/适应世界模型同样超过随机与静态验证器；排名准确率上升、Brier score 下降，说明预测质量改善。

### GUI

在 `MiniWoB++` 与 `OSWorld` 上，任务完成率提升，平均动作数相对基线减少 **39.4%**，表明预测引导减少了无效探索。

### 实验室规划

五个连续保留的 4B 策略版本：Final Score 从 **21.80%** 提升至 **46.01%**（超过翻倍）。与参考系统对比（L2 Final）：

| 系统 | L2 Final |
|------|----------|
| Grok 4.3 | 0.3244 |
| Gemini 3.1 Pro | 0.3263 |
| GPT-5.5 | 0.2276 |
| Kimi K2.6 | 0.3150 |
| Qwen3.6-35B-A3B（训练后） | 0.4100 |
| Actor–Simulator–Selector 参考 | 0.4532 |
| **RSI-Anything (4B)** | **0.4601** |

### 反应优化

- Pd–NHC–DMS（GC，20 次实验）：最优观测产率 93.0% vs 贝叶斯优化 87.5%（+5.5 个百分点）。
- Pd(OAc)₂ flow LC–MS（40 次实验）：平均最优观测产率 **96.15%** vs 贝叶斯优化 **82.16%**（+13.99 个百分点）。

### 免疫科学端到端

Agent Genesis 搜索并保留模型构建工作流 → 得到动作条件免疫世界模型 → 分析 agent 结合模型预测与实验证据进行自校正，最终提名 SIRPα 抑制与 IL-36γ 轴调节的联合治疗假设。

## 深度分析

### 耦合更新为何是难点

策略更新会改变候选分布，使原世界模型的训练支撑失效；世界模型更新会改变排序与想象轨迹，从而改变策略学习的信号。因此单独提升任一组件并不保证系统级收益。RSI-Anything 通过显式的组件检查与兼容性检查，把「是否保留」变成可设计的门控，而不是隐式希望联合训练自然收敛。

### 可靠性与覆盖的边界

可靠性评估严格限定在「当前模型版本 + 已覆盖候选范围」。这避免了用过时预测或外推区域的乐观误差去触发适应，但也意味着：若选择策略过于集中，世界模型可能长期停留在局部可靠区。论文用「insufficient」状态显式处理覆盖不足，是工程上务实的选择。

### 跨域通用性的来源

通用性主要来自三层抽象：

1. `JEPA-Anything` / OPF 提供的跨域表征预测接口；
2. 「预测 → 选择 → 反馈 → 更新 → 检查 → 保留」的统一协议；
3. 域侧只负责动作编码、结果读出与启用路径配置。

实验覆盖了软件（代码、GUI）、物理规划与湿实验科学，说明该协议对「可执行候选 + 可观测反馈」的任务类具有较好的可迁移性。

### 与贝叶斯优化等搜索方法的关系

在反应优化中，RSI-Anything 不是简单的另一套采集函数，而是把「可保留的系统更新」纳入循环：世界模型与选择策略都可以随反馈演化并被检查后固化。这解释了为何在相同实验预算下能拉开与标准贝叶斯优化的差距。

## 局限

- 代码修复实验固定了编码器，报告的增益主要反映选择器与世界模型适应的贡献，不能直接外推到端到端代码智能体的完整增益。
- 可靠性与兼容性检查的具体准则依赖实现细节与阈值，跨域统一的自动调参仍需额外工程；实际部署仍需领域知识。
- 覆盖不足时的行为偏保守：不触发适应可能延迟模型对策略漂移的响应。
- 负结果与失败模式的系统分析较少；在何种分布偏移下保留协议会拒绝有益更新或错误接受有害更新，仍需更多证据。
- 免疫科学应用展示了流程连通性，但治疗假设的实验验证超出本文范围。

## 我的笔记

**可直接复用的设计模式**

- 把「保留的策略–模型对」当作系统状态变量，而不是只跟踪最新策略或最新模型。
- 版本感知的可靠性评估：历史预测只用于分析，不混入当前误差。
- 预算显式记账：外部反馈次数、适应计算、接受检查分开报告，便于与基线公平对比。
- 异步更新 + 双门控：允许策略与模型以不同频率更新，再用兼容性检查保证联合行为。

**实现检查清单**

1. 候选生成器与世界模型解耦。
2. 执行接口只返回真实观测，不泄露未执行候选的标签。
3. 可靠性模块必须能重放「当前版本在历史输入上的预测」。
4. 保留决策同时记录组件分数与兼容性分数，便于事后审计。
5. 所有在线调用次数与实验次数与基线对齐后报告。

**后续值得追问的问题**

- 兼容性检查能否用可学习的元评判器替代手写规则？
- 在更长视野的多轮科学实验中，如何检测并响应缓慢的分布漂移？
- 当策略与世界模型联合梯度更新时，保留协议是否需要改为「检查点 + 回滚」语义？
